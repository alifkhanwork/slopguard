**SlopGuard** is a production-grade, install-time verification layer built to stop **slopsquatting** — a novel supply-chain attack vector where malicious actors register the exact hallucinated package names that AI coding agents (such as LLM pair programmers) tend to invent, then wait for agents or developers to install them automatically.

Created and maintained by [SILICON VALLEY GLOBAL PH INC](https://svg.ph/).

## ⚠️ The Problem

AI coding assistants (such as Claude, ChatGPT, Copilot, or local LLM agents) frequently invent package names that sound plausible but do not actually exist. This typically occurs when an LLM blends two real, popular packages together (for example, hallucinating `react-codeshift` by merging `jscodeshift` and `react-codemod`).

### Why Slopsquatting is Dangerous
1. **Predictable & Repeatable**: These AI hallucinations are highly deterministic across runs of the same model. Attackers run popular LLM prompts, log hallucinated package names, and pre-register them on public registries like PyPI and npm.
2. **Traditional Typosquat Scanners Fail**: Existing typosquatting detectors work by comparing a requested package name against popular existing packages for single-character distance or typos (e.g. `reqeusts` vs `requests`). Hallucinated names are brand-new, valid English phrases or compound names with no direct single-name typosquat collision.
3. **Silent Code Execution**: When a developer or AI agent executes `pip install <hallucinated-pkg>` or `npm install <hallucinated-pkg>`, an install command that would have returned a 404 error last week now silently succeeds — executing malicious `setup.py` scripts or post-install hooks directly inside your environment or CI pipeline.
4. **Vulnerability Scanners Don't Help**: Scanners like `npm audit` check for known vulnerabilities inside legitimate packages. They cannot detect whether a newly published package is a freshly registered trap with zero software history.

**SlopGuard closes this gap** by verifying what an agent or developer is about to install *before* execution occurs.

## 🧩 Key Architecture Pillars

### 1. Hallucination Detection Engine (`slopguard/detection/`)
- `conflation.py` (`name_conflation.py`) — Detects when a candidate package name looks like an LLM blend of two real, popular package names (e.g. blending `jscodeshift` + `react-codemod` → `react-codeshift` or `fastapi` + `pydantic` → `fastapi-pydantic`).
- `cross_registry.py` — Flags names that exist on one registry (e.g. PyPI) but not the target registry being installed from (e.g. npm). Attackers frequently exploit cross-ecosystem confusion to register npm packages under popular PyPI names.
- `novelty.py` (`novelty_check.py`) — Flags brand-new, unestablished packages (<14 days old) combined with low release history, the core signature of an active slopsquat campaign.

### 2. Registry Trust Scorer (`slopguard/scoring/trust_score.py`)
- Pulls live package metadata from PyPI JSON API and npm registry API: package age, download count and recent velocity, maintainer account history, and publish-burst patterns (e.g. many packages published from one account in a short window).
- Combines signals into a single, documented, configurable weighted risk score (0–100) — avoiding black-box decisions.

### 3. Install-Time Interceptor (`slopguard/interceptor/shell_hook.py`)
- Hooks directly into `pip install` and `npm install` command lines — including multi-package installs and commands generated by AI coding agents.
- Fast-paths well-established, low-risk packages so normal development is never slowed down.
- Provides a **CI / Non-Interactive Fail-Safe**: never hangs in CI environments, hard-blocking high-confidence malware while logging warnings for lower-confidence heuristic flags.

### 4. Threat Intel Sync (`slopguard/intel/feed_sync.py`)
- Integrates with an actively maintained malicious-package database (OpenSSF Malicious Packages DB via the OSV API at `api.osv.dev`) rather than maintaining a fragile proprietary feed.
- Local caching (`~/.slopguard/intel_cache.json`) with graceful offline fallback to local heuristic detectors when network is unavailable.

### 5. Agent Tooling Integration (`slopguard/integrations/agent_permit.ts` / `@svgph/slopguard`)
- Plugs directly into `agent-permit` as an inline pre-approval check (`checkPackage()`), so any connected agent tool gets slopsquatting protection automatically with zero extra setup.

## 📊 Detection Signals

| Signal | What it Catches | Confidence Level |
| :--- | :--- | :--- |
| **Name Conflation** | Hallucinated blends of two real popular packages | Medium |
| **Cross-Registry Mismatch** | Name confusion between PyPI and npm ecosystems | Medium |
| **Package Novelty + Spikes** | Freshly registered package name with sudden install activity | High |
| **Publish Burst** | Multiple packages published from one account in a short window | High |
| **Known Threat Feed Match** | Name matches a documented active malware campaign in OSV | Highest |

> **Note:** Only high-confidence signals (or a high composite risk score) trigger a hard block by default. Lower-confidence signals emit warnings to prevent false positives from slowing down legitimate development.

## 💻 Quickstart

### Installation

#### Python Package Core
```bash
pip install slopguard
```

#### TypeScript / Node.js Bindings
```bash
npm install @svgph/slopguard
```

---

### Command Line Usage

#### 1. Check a package before installing
```bash
slopguard check react-codeshift --ecosystem npm
```

#### 2. Install with built-in protection
```bash
slopguard install react-codeshift --ecosystem npm
```

#### 3. Scan an existing project lockfile or requirements file
```bash
slopguard scan-lockfile ./package.json
slopguard scan-lockfile ./requirements.txt
```

#### 4. Manually refresh threat intelligence feed
```bash
slopguard update-intel
```

## ⚙️ Configuration

SlopGuard can be configured per project via `.slopguard.json` in your repository root, or globally in `~/.slopguard/config.json`:

```json
{
  "interceptor_mode": "block",
  "warn_threshold": 40.0,
  "block_threshold": 75.0,
  "enabled_registries": ["npm", "pypi"],
  "allowlist": [
    "my-internal-private-package"
  ],
  "intel_sync_enabled": true,
  "feed_cache_ttl_hours": 24
}
```

## 🔌 Agent Integration Example

Integrate SlopGuard into your agent pre-approval system or `agent-permit`:

```typescript
import { checkPackage } from "@svgph/slopguard/integrations/agent-permit";

const result = await checkPackage("react-codeshift", "npm");

if (result.riskScore >= 75) {
  console.error(`[SlopGuard] Blocked suspicious package: ${result.packageName}`);
  // agent-permit blocks the install action here
}
```
